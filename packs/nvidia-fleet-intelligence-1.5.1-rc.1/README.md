# NVIDIA Fleet Intelligence

Palette add-on pack wrapping the upstream `fleet-intelligence-agent` Helm chart,
version `1.5.1-rc.1` (app version `1.5.1-rc.1`), from the NVIDIA DSX AI Factory
project: <https://github.com/dsx-ai-factory/fleet-intelligence-agent>.

The chart deploys the Fleet Intelligence Agent as a DaemonSet that runs on every
GPU node and collects GPU metrics, events, machine inventory, and component
health, then exports them to the Fleet Intelligence backend. An optional OTel
gateway collector can be deployed alongside the agents.

Generated by packify on 2026-11-12; the upstream chart documentation below has
been adapted for Palette (namespace, release name, mirrored images, and install
steps).

## Prerequisites

- A running Kubernetes cluster with Helm-based add-on support in Palette.
- The NVIDIA GPU Operator installed, with DCGM enabled. The agent talks to the
  DCGM HostEngine (`nvidia-dcgm.gpu-operator.svc:5555` by default) and only
  schedules onto nodes labeled `nvidia.com/gpu.deploy.dcgm=true`, which the GPU
  Operator sets automatically.
- An `nvidia` RuntimeClass available on the target nodes (the DaemonSet uses
  `runtimeClassName: nvidia` by default).
- For air-gapped or offline environments, mirror the two images listed under
  [Mirrored images](#mirrored-images).

## Installation

In Palette, add this pack to an add-on profile and deploy it to a cluster. The
pack creates the `fleet-intelligence` namespace and installs the
`fleet-intelligence-agent` Helm release into it. Configure the values under
`charts.fleet-intelligence-agent`.

To enroll agents with the Fleet Intelligence backend, set `enroll.enabled: true`
and provide `enroll.endpoint` plus either `enroll.tokenValue` or the name of an
existing secret in `enroll.tokenSecretName` / `enroll.tokenSecretKey`. Leave
enrollment disabled to run the agents in standalone mode.

### Enrollment (per node via init container)

`enroll.enabled` and `enroll.unenroll` are mutually exclusive; do not set both to `true`.
Set `enroll.force=true` to append `--force` to the fleetint enrollment command.
Set `enroll.nodeGroup` / `enroll.computeZone` to pass optional enrollment metadata via the init container command.

### OTel gateway (optional)

Set `otelGateway.enabled: true` to deploy a `fleetint-otelcol` collector
Deployment and Service alongside the agents. When enabled:

- Agent OTLP traffic is sent to the gateway through `FLEETINT_COLLECTOR_ENDPOINT`
  rather than directly to the backend.
- The gateway holds the backend credentials and authenticates outbound requests
  with its JWT; agents never see them. Agent identity flows through OTLP
  resource attributes (`machine.id`, GPU UUIDs).
- Agent enrollment remains direct, because inventory and attestation use the
  agent's own backend identity independently of OTLP export.
- A NetworkPolicy restricts unauthenticated OTLP ingress to this release's pods
  (requires a CNI that enforces NetworkPolicy), and a PodDisruptionBudget keeps
  at least one gateway replica available.

Configuration is under `otelGateway`, including `image.repository`,
`replicas`, `enroll.endpoint`, `enroll.sakToken` (or `enroll.existingSecret`,
whose secret must carry a `sak-token` key), `backendEndpoint`, and
`memoryLimiter` thresholds. `resources.limits.memory` is required when the
gateway is enabled: the collector's memory limiter reads the container's cgroup
limit, and rendering without one is rejected.

## Notes

- The chart assumes the DCGM HostEngine is already running in the cluster
  (typically via the NVIDIA GPU Operator). Set `env.DCGM_URL` to match your DCGM
  Service.
- The DaemonSet uses `runtimeClassName: nvidia` by default.
- **Node scheduling**: the agent requires a running DCGM HostEngine to collect
  GPU metrics, so it only deploys to nodes where DCGM is present (labeled
  `nvidia.com/gpu.deploy.dcgm=true`). The NVIDIA GPU Operator sets this label
  automatically when DCGM is enabled. To override, set a different
  `nodeSelector`, or remove the restriction by setting it to `{}`.
